Übersicht

Am Ende läuft die Website von Penguin Jump auf deinem Hetzner-Server unter einer eigenen Subdomain, zum Beispiel spiel.domain-a.ch. Dort gibt es:

  • die Startseite mit den Downloads (Windows-Installer, Linux, Android),
  • das Spiel im Browser unter /play/, die Community-Level und die Bestenlisten,
  • das Konto-Panel für Spieler unter /konto/ und das Admin-Panel unter /admin/.
SpielerBrowser, Windows, Linux, Android
spiel.domain-a.chHestiaCP · PHP 8.3 · MariaDB
Website, API, Admin-Panel
GitHub ReleasesDownloads (signiert)

Die Downloads selbst liegen weiterhin bei GitHub; dein Server liefert die Website, das Spiel im Browser, die Level, die Konten und die Bestenlisten. Rechne mit etwa 45 Minuten, plus Wartezeit, bis DNS und SSL greifen.

Was du brauchst

  • Deinen HestiaCP-Server aus der ersten Anleitung (Schritte 1–7 erledigt, Anmeldung als web klappt)
  • FileZilla (wie in der ersten Anleitung)
  • Eine Authenticator-App auf dem Handy (z. B. Aegis, 2FAS, Google oder Microsoft Authenticator)
  • Den Projektordner Claude Game auf deinem PC (für das Werkzeug „Konfiguration-Erstellen“)
  • Einen Passwort-Manager für die neuen Passwörter

Schritt 1: Subdomain im DNS eintragen

Die Subdomain spiel soll auf deinen Server zeigen. Weil deine DNS-Zone auf dem eigenen Server liegt, trägst du das direkt in HestiaCP ein.

  1. In HestiaCP als web anmelden (wie in der ersten Anleitung, Schritt 4.2).
  2. Oben auf DNS → bei domain-a.ch auf Einträge → Eintrag hinzufügen.
  3. Name: spiel, Typ: A, IP/Wert: SERVER-IP → Speichern.
Soll das Spiel eine eigene Domain bekommen (statt einer Subdomain), legst du sie wie in der ersten Anleitung (Schritt 5 und 6) an – mit DNS-Unterstützung und Nameserver-Umstellung bei Metanet – und überspringst diesen Schritt.

Prüfen (nach ein paar Minuten) in PowerShell: nslookup spiel.domain-a.ch muss SERVER-IP zeigen.

Schritt 2: Web-Domain anlegen

  1. Oben auf WEB → Web-Domain hinzufügen.
  2. Domain: spiel.domain-a.ch
  3. IP-Adresse: SERVER-IP
  4. DNS-Unterstützung und Mail-Unterstützung nicht anhaken – die Subdomain steckt schon in der Zone von domain-a.ch.
  5. Speichern.

HestiaCP legt den Ordner /home/web/web/spiel.domain-a.ch/public_html an. Dorthin kommt später die Website.

Schritt 3: SSL, PHP und Web-Ordner einstellen

In der Liste unter WEB bei spiel.domain-a.ch auf Bearbeiten (Stift).

3.1 SSL (HTTPS) – erst wenn Schritt 1 greift

  1. Haken bei SSL aktivieren, dann Let's Encrypt verwenden.
  2. Zusätzlich Automatische HTTPS-Weiterleitung aktivieren und HSTS aktivieren.

3.2 PHP-Version und Web-Ordner

  1. Erweiterte Optionen aufklappen.
  2. Backend-Vorlage PHP-FPM: PHP-8_3 (oder neuer) wählen.
  3. Haken bei Benutzerdefiniertes Dokumentenstammverzeichnis (Custom document root): Ziel-Domain spiel.domain-a.ch, Verzeichnis public.
  4. Speichern.
Warum der Ordner public? So sind nur die öffentlichen Dateien im Internet erreichbar; Programmcode, Konfiguration und Level liegen eine Ebene darüber. Findest du die Option nicht, geht es auch ohne: Dann sperrt eine mitgelieferte .htaccess die übrigen Ordner.
Die Proxy-Vorlage (NGINX) muss auf default bleiben. Eine Vorlage wie „force-https“ ist in Ordnung, aber keine, die nur statische Dateien ausliefert.

Schritt 4: Datenbank anlegen

  1. Oben auf DB → Datenbank hinzufügen.
  2. Datenbank: spiel – HestiaCP macht daraus web_spiel.
  3. Benutzername: spiel – wird zu web_spiel.
  4. Passwort: Generieren und sofort im Passwort-Manager speichern.
  5. Typ: mysql (das ist MariaDB) → Speichern.

Schritt 5: Postfach für die Codes (freiwillig)

Spieler können beim Konto freiwillig eine E-Mail-Adresse hinterlegen. Dann schickt die Website Bestätigungs-Codes und Codes für ein vergessenes Passwort. Ohne Postfach funktioniert alles andere trotzdem – Spieler setzen ihr Passwort dann mit ihrem Wiederherstellungs-Code zurück.

  1. Oben auf MAIL. Gibt es domain-a.ch noch nicht als Mail-Domain: Mail-Domain hinzufügen → domain-a.ch (mit DKIM) → Speichern.
  2. Bei domain-a.ch auf Konten → Konto hinzufügen.
  3. Konto: spiel → Adresse spiel@domain-a.ch. Passwort generieren und speichern.
  4. Speichern. Rechts zeigt HestiaCP die Zugangsdaten (SMTP-Server, Port).
Für Schritt 7Wert
Mailservermail.domain-a.ch (oder der Name, den HestiaCP bei SMTP anzeigt)
Port / Verschlüsselung587 / STARTTLS
Benutzerspiel@domain-a.ch
Passwort(aus dem Passwort-Manager)
Damit die Mails nicht im Spam landen, müssen in der DNS-Zone von domain-a.ch die Einträge für MX, SPF (TXT v=spf1 …) und DKIM stehen. HestiaCP legt sie beim Anlegen der Mail-Domain automatisch an, wenn die Domain seine DNS-Zone nutzt.

Schritt 6: Website-Paket holen

Bei jedem Hochladen des Codes auf GitHub baut GitHub automatisch eine neue Version – mit fertigem Website-Paket.

  1. Öffne github.com/MischaFierz/penguin-jump/releases und nimm die oberste (neueste) Version.
  2. Lade PenguinJump-website.zip herunter.
  3. Entpacke das ZIP in einen Ordner, z. B. Downloads\PenguinJump-website.

Darin findest du diese Ordner:

Schritt 7: Konfiguration erstellen

Die Datei config/config.php enthält die Zugangsdaten und zwei geheime Schlüssel. Ein Werkzeug erstellt sie für dich:

  1. Im Projektordner eine Eingabeaufforderung öffnen (im Explorer in die Adressleiste cmd tippen, Enter).
  2. Eingeben: Konfiguration-Erstellen.cmd "C:\Users\…\Downloads\PenguinJump-website" (dein Ordner aus Schritt 6).
  3. Die Fragen beantworten: Datenbank aus Schritt 4, Postfach aus Schritt 5 (leer lassen = ohne E-Mail).
  4. Am Ende steht der Setup-Token. Notiere ihn – du brauchst ihn in Schritt 9.
config.php enthält Passwörter. Nie per E-Mail oder Chat verschicken und nicht ins Git-Projekt kopieren. Eine Sicherheitskopie gehört in den Passwort-Manager.

Schritt 8: Mit FileZilla hochladen

  1. Falls noch nicht vorhanden: In HestiaCP bei WEB → spiel.domain-a.ch → Bearbeiten → Zusätzliches FTP-Konto anlegen (wie in der ersten Anleitung, Schritt 7). Benutzer z. B. web_spielftp, Pfad leer lassen.
  2. FileZilla öffnen, oben eintragen: Server ftpes://spiel.domain-a.ch, Benutzer und Passwort des FTP-Kontos, Port leer → Verbinden.
  3. Rechts (Server) in den Ordner public_html wechseln und die Standard-Datei index.html löschen.
  4. Links (dein PC) in den Ordner PenguinJump-website wechseln, alles markieren (Strg+A) und nach rechts in public_html ziehen.

Danach liegt z. B. public_html/public/index.php und public_html/config/config.php auf dem Server. Wichtig: Auch die unsichtbaren .htaccess-Dateien müssen mit (FileZilla: Menü Server → Anzeige versteckter Dateien erzwingen).

Schritt 9: Einrichten im Browser

  1. Öffne https://spiel.domain-a.ch/setup.
  2. Setup-Token aus Schritt 7 eintragen, einen Benutzernamen für das Admin-Panel und ein starkes Passwort wählen → Weiter. Die Datenbank-Tabellen und die 12 Hauptlevel werden jetzt angelegt.
  1. Du landest im Admin-Panel. Melde dich mit dem neuen Zugang an.
  2. Zwei-Faktor einrichten: In der Authenticator-App „Konto hinzufügen → Schlüssel eingeben“ wählen und den angezeigten Schlüssel abtippen. Den 6-stelligen Code aus der App eingeben → Bestätigen.
Geschafft: Unter Hauptlevel bearbeitest und veröffentlichst du die Level, unter Admin-Benutzer legst du weitere Personen mit Stufen und Rechten an (sie setzen bei der ersten Anmeldung ein eigenes Passwort und richten 2FA ein).

Schritt 10: Spiel mit dem Server verbinden

Das Spiel im Browser (/play/) findet den Server von selbst. Die Windows-, Linux- und Android-Version brauchen die Adresse einmal fest eingebaut:

  1. Im Projektordner die Datei game.json öffnen.
  2. "baseUrl": "" ändern zu "baseUrl": "https://spiel.domain-a.ch" und speichern.
  3. Die Änderung auf GitHub hochladen (oder Claude sagen: „baseUrl ist https://spiel.domain-a.ch, bitte pushen“).
  4. GitHub baut eine neue Version. Ihr PenguinJump-website.zip wie in Schritt 11 hochladen.

Ab dieser Version laden die Spiele die Hauptlevel vom Server, zeigen Community-Level und Bestenlisten und installieren neue Versionen selbst.

Schritt 11: Neue Versionen einspielen

  1. Neuestes PenguinJump-website.zip von GitHub holen und entpacken.
  2. Den Ordner config im entpackten Paket löschen – so bleibt deine config.php auf dem Server unberührt.
  3. Alles mit FileZilla nach public_html ziehen und bei der Frage Überschreiben wählen.
  4. Einmal https://spiel.domain-a.ch/setup?update=SETUP-TOKEN öffnen. Das ergänzt neue Datenbank-Tabellen, falls die Version welche mitbringt („Datenbank ist auf dem neuesten Stand“).
Spieler, die das Spiel installiert haben, bekommen die neue Version beim nächsten Start angeboten – aber erst, wenn die neue version.json auf deinem Server liegt. Die Hauptlevel änderst du dagegen jederzeit direkt im Admin-Panel, ohne neue Version.

Sicherheit und Backups

  • Schlüssel sichern: Der Ordner Claude Game-keys neben dem Projekt (Signier-Schlüssel für Updates und Android) gehört auf einen USB-Stick oder in den Passwort-Manager. Ohne ihn lassen sich installierte Spiele nicht mehr aktualisieren.
  • Backups: HestiaCP sichert unter BACKUP täglich Website und Datenbank. Lade ab und zu eines herunter.
  • Admin-Zugänge: Jeder hat seinen eigenen Zugang mit 2FA. Gib Stufen sparsam: „Level-Editor“ darf nur Hauptlevel bearbeiten, „Moderator“ nur Community und Bestenlisten.
  • Verlauf: Unter Verlauf im Admin-Panel steht jede Änderung und jeder abgelehnte (geschummelte) Lauf.
  • Updates des Servers: Wie in der ersten Anleitung (Schritt 10) – apt update && apt upgrade regelmässig.

Fehlersuche

ProblemLösung
„Server not configured yet“config/config.php fehlt auf dem Server – Schritt 7 und 8 prüfen.
Weisse Seite oder Fehler 500HestiaCP → WEB → spiel.domain-a.ch → Logs (Fehlerprotokoll). Meist falsche Datenbank-Angaben in config.php oder PHP älter als 8.1.
Seite zeigt Ordnerinhalt oder QuelltextDie .htaccess-Dateien fehlen (versteckte Dateien in FileZilla anzeigen) oder der Web-Ordner zeigt nicht auf public.
Fehler zu sodium oder pdo_mysqlPHP-Version in Schritt 3.2 auf PHP-8_3 stellen; auf dem Server: apt install php8.3-mysql.
Zertifikatsfehler / kein HTTPSDNS-Eintrag (Schritt 1) wirkt noch nicht. Warten, dann SSL in Schritt 3.1 erneut speichern.
Keine E-MailsAdmin-Panel → Einstellungen → Test-E-Mail senden. Fehlermeldung lesen; Postfach-Daten in config.php prüfen, Spam-Ordner prüfen.
2FA-Code wird abgelehntUhrzeit auf dem Handy automatisch stellen lassen. Ein anderer Admin kann unter Admin-Benutzer „2FA zurücksetzen“.
Setup-Token vergessenSteht in config/config.php auf dem Server (setup_token).

Checkliste

  • DNS: spiel zeigt auf SERVER-IP (Schritt 1)
  • Web-Domain spiel.domain-a.ch angelegt (Schritt 2)
  • SSL mit Let's Encrypt, HTTPS-Weiterleitung und HSTS aktiv (Schritt 3.1)
  • PHP 8.3 und Web-Ordner public eingestellt (Schritt 3.2)
  • Datenbank web_spiel angelegt, Passwort gespeichert (Schritt 4)
  • Freiwillig: Postfach spiel@domain-a.ch (Schritt 5)
  • Website-Paket geholt und entpackt (Schritt 6)
  • config.php erstellt, Setup-Token notiert (Schritt 7)
  • Alles inklusive .htaccess in public_html hochgeladen (Schritt 8)
  • Setup ausgeführt, Admin-Zugang mit 2FA eingerichtet (Schritt 9)
  • baseUrl in game.json eingetragen und neue Version hochgeladen (Schritt 10)
  • Test: Konto unter /konto/ erstellen, ein Level im Browser-Spiel bauen und veröffentlichen
  • Schlüssel-Ordner Claude Game-keys gesichert
